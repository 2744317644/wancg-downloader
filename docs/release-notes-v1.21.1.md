## 修复分类页「加载更多失败」与加载时掉帧

### 1. 加载更多总是失败、要下拉刷新才能恢复

根因有两个：

- 触底哨兵用 `.id(...)` 强制重建，加载成功的一瞬间哨兵会立刻再次触发，短时间连续拉取多页；站点对短时间内的高频请求返回 **HTTP 429 限流**，于是页面显示“加载失败”；
- 请求没有节奏控制，失败后只能等用户下拉刷新重置。

修复：

- 触底哨兵改为**稳定 identity**，只在下一次真正滚动到底时再次触发，不再连环加载；
- 页面请求增加 **1.1 秒最小间隔**，并给下一页请求带上 `Referer`；
- 对 `next` 链接回环、空列表页做保护，避免在同一条游标上原地打转；
- 429 时给出明确提示（“访问太频繁，被站点限流”），底部同时提供一个显式的**「加载更多」按钮**作为兜底/手动重试入口；
- 下拉刷新失败不再清空已加载内容。

### 2. 加载更多时掉帧

- 语言/AI 分类原来在每次视图更新时对每部作品的标题重新做一遍上百个标记匹配；现在改为**解析时分类一次并缓存**，`visibleAlbums` 也缓存在 feed model 里；
- 封面卡片实现 `Equatable`，追加一页时已显示的卡片不再整体重建；
- 网格外层去掉无必要的 `LazyVStack` 嵌套，减少追加时的整树重排；
- 缩略图 JPEG 编码从主线程移到后台队列（一页 20 张封面同时解码时不再卡主线程）。

### 验证

iOS 模拟器 UI 压力测试连续加载 4 轮，已加载作品数 **60 → 80 → 100 → 120 → 140**，全程**没有出现加载失败**；下拉刷新正常；Release 编译与代理/解析 smoke test 通过。
